# 角色与业务状态复现

给开发复现正常、空态、失败或权限边界时，在当前规划版 spec.json 添加可命名的 `replay_cases`。同一版本的预设数据随内容冻结，不把真实用户输入或 localStorage 转成分享链接。

```json
{"replay_cases":[{
  "id":"viewer-empty", "title":"只读用户没有订单", "role":"viewer",
  "scenario":"empty", "pages":["order-list","order-detail"],
  "requirement_ids":["FR-ORDER-002"],
  "source":"ai-inferred", "status":"pending",
  "state":{"orders":[],"filter":""}
}]}
```

最多 30 个场景，state 是最多 32KB 的 JSON 对象，仅放合成数据；role、scenario 在独立字段声明。scenario 支持 normal/empty/loading/error/forbidden。场景 ID、角色含义、页面关联与需求规则应保持一致。场景按业务风险选择，不为每个页面机械生成全排列；缺依据的角色权限标为 pending，不能把演示实现当作业务已确认。

## 页面接入

使用本版共享 runtime（含 PS_REPLAY_V1）及重新编译的 spec-data.js。运行时在页面业务 JS 执行前注入场景 state、role、scenario；页面从 PSPrototype.readState() 读取，并通过 writeState() 保存模拟变更。角色的可见性、禁用和提交校验由业务 JS 真正实现，不是切换文字标签。可以参考 order-demo 的 operator/viewer/guest 合成案例。

state 字段是页面业务数据契约，公共运行时不推断其语义。与 PRD 的字段、初始值、流程和权限对齐。跨页流程的各目标页必须列在 pages 中，并能读取同一数据结构；自定义跳转需携带与共享 navigate 相同的复现上下文。复现场景不模拟登录，更不能作为真实系统权限控制。

## 使用与隔离

- “复现场景”选择一个预设，切换时从该场景起点重新开始。普通演示仍使用原先按项目/版本隔离的 localStorage。
- “复现链接”显示只读的项目固定入口与独立原型链接，可选中复制。链接只含项目、版本和场景 ID；固定入口还包含版本/模块/页面路径。分享的是预设起点，不是表单输入、操作录像、弹框当前位置或批注。
- 复现使用内存及 sessionStorage 中独立的运行 ID；共享 navigate 保留该运行上下文，支持创建/修改后跨页查看。分享链接不带运行 ID，收件人重新从预设开始。浏览器禁止 sessionStorage 时仍可演示当前页，但跨页修改可能无法保留，工具栏明确提示，不能声称已完整复现。
- 复现模式不允许自由切换基础 scenario，避免角色与状态组合偏离预设；业务操作仍能推进数据与状态。重置回当前预设，普通演示与批注不受影响。选择“普通演示”返回原有本机模拟数据。
- 项目/版本不匹配、页面不支持场景、场景已移除时显示失败，并使 main 内容不可操作。不要自动跳到最新版本或正常状态掩盖失效链接。
- 工作版场景可变化；正式交接先按用户授权创建冻结修订，再从该修订分享。历史资源不能原地升级。旧无 replay_cases 的版本保持原行为。
- file:// 链接不是团队在线地址；要让其他设备访问，需要用户提供固定托管或共享服务，不能自动部署。URL 不带原始数据，但部署的 spec 本身包含合成数据，仍不可放密钥或隐私信息。

## 验收

必须实际验证：独立页面和固定入口 iframe 打开同一场景；只读角色禁止修改但可查看；失败/空态与正常不同；跨页保留本次模拟修改；再次打开分享链接回到预设；重置与切普通演示不污染原数据；错误项目/版本/场景拒绝；历史版本保持独立。验证自定义脚本时也检查提交端分支，而不仅是按钮样式。静态校验只证明字段及关联合法，不证明权限和业务状态已实现。
