# 内容取舍与语义复核

编写 PRD 时用于判断哪些信息值得保留；结构、字段及执行检查分别由下列文档负责，不另维护第二份清单。

- 写入前判断：是否改变本次开发行为、测试预期、数据口径或设计状态？有影响才写，没有则省略或引用已有约定。
- 简洁不能省略独有条件；按实际复杂度选择短规则、分项、表格和实例。避免套话、重复摘要以及为了填模板增加无关能力。
- 信息依据与未知项处理见 SKILL.md；不得为了报告通过把阻塞问题降级、把推断当作已确认事实。

| 复核对象 | 详细规范 |
| --- | --- |
| 章节完整、背景目标、成功指标与功能验收的区别 | [standard-prd.md](standard-prd.md) |
| 功能入口、字段、结果、异常、关键边界与可观察验收 | [functional-detail.md](functional-detail.md) |
| 跨章节与原型、测试、交接的去重及正文归属 | [information-architecture.md](information-architecture.md) |
| 输入覆盖、适用性、报告状态及生成后的核对步骤 | [quality-contract.md](quality-contract.md) |

语义复核必须对照原始方案的独立约束及实际画面；引用有效、章节齐全或登记为 covered 都不能证明业务信息已经写全。生成用例、原型检查和真实产品测试结果分别记录。
