# 标准 PRD 与文件附录

新建项目必须使用九章标准结构。`content/prd.json` 只登记章节和来源，不存第二份需求正文。章节固定为：版本说明与本版范围、用户与业务流程、功能需求与页面规则、数据与埋点、非功能需求、验收与上线条件、里程碑与计划、风险与待决策、附录与参考资料。

## 同源与裁剪

- 本版范围复用 overview/index.md；功能章节读取 spec.json；原型“本页需求”按页面和控件引用同一 spec，不另写一份页面 PRD。
- 验收章节自动引用 spec 中的验收条件。测试、上线、需求范围与交接是执行/汇总视图，不再维护另一套业务规则。改变业务规则时先改源，再复核受影响流程和测试。
- 每章必须判断适用性，不按章节数量编造内容。正文顶部使用 `<!-- prd-status: provided -->`、`pending` 或 `not_applicable`，并用 `<!-- prd-reason: 原因 -->` 说明。编辑器可编辑这些 Markdown 元数据；阅读和导出隐藏元数据语法并显示中文状态。
- provided 仅表示内容已提供，不等于需求确认；不适用必须说明原因；未知负责人、日期、性能阈值、合规条件均写待确认，不伪造承诺。
- 埋点至少写事件、触发条件、字段类型/口径、去重、授权、验证方式；非功能逐项判断性能、安全、兼容性、可用性、无障碍、隐私与合规。计划写交付物、负责人、依赖、日期、退出条件；风险写影响、应对、责任人、期限和状态。
- 目录显示九章，旧路由保留；完整 Markdown 导出包含所有章节与附件路径，不仅导出编号。Agent 修改具体规则仍按稳定 ID 最小修改，禁止整版重生成。

## 附件实际保存

通过 `scripts/edit_project.py <项目根> --version <版本>` 启动本机编辑器，在物料选择中打开“附录 · 文件附件”。选择文件、填写说明、可选关联需求编号、确认分享范围后上传。未保存的正文草稿必须先保存或明确丢弃，避免上传刷新覆盖草稿。

文件保存为项目根 `attachments/<唯一ID>/file.<扩展名>`；同名文件不会覆盖，meta.json 保存原名、说明、版本、时间、关联需求、大小和 SHA256。规划版在 content/attachment-refs.json 绑定 ID 和摘要；后续冻结/交接继承引用。复制、压缩、备份或部署项目时必须包含 attachments 目录，单独发送 HTML 不能携带附件。

冻结后上传进入项目级补充资料，明确标注“冻结后补充”，不写冻结版本，也不冒充原交接依据。补充资料不会自动进入下一版范围；如需纳入，由 Agent 明确登记引用并验证。上传为追加操作，暂不提供删除/替换 UI；修改资料使用新附件并说明替代关系。

本机编辑器使用会话令牌、来源检查和并发版本校验；下载按当前版本引用限制。静态 HTML 仅链接已保存附件，不显示虚假的上传成功。若需多人在线上传，必须另行提供有身份鉴权、权限和存储管理的服务，不能把本机编辑器开放到公网。

单文件上限 10MB，允许 PDF、PNG/JPEG、UTF-8 TXT/MD/CSV、无宏 DOCX/XLSX/PPTX；拒绝 HTML/SVG、脚本、压缩包、可执行文件及不匹配格式。格式检查不是病毒扫描，也不证明资料可信；敏感资料须获授权，公司如有要求应接入文件扫描。默认下载，不在线执行或预览附件。

上传落盘后构建失败会返回已保存及错误，不要重复上传；先修复并 build。若进程在文件落盘、引用登记之间中断，会留下未引用文件：Agent 核对 attachments 元数据、实际摘要与目标规划版本，恢复缺失引用后重新验证；不要删除或覆盖已有文件。

## 旧项目兼容

没有 prd.json 的历史项目仍按旧目录展示，不自动重生成或改快照。用户要求升级时，先审查手改与备份，在规划版登记九章并引用已有正文，不复制已存在规则；新缺章标待补。可用 prdlib.initialize 初始化缺省文件后调整来源映射，但不得对冻结版本执行。升级项目壳及根目录构建依赖也须保留手改并单独验证；普通 build 不负责安装新版壳。只升级 Skill 不代表既有 HTML 已升级。
