# 控件的数据与交互说明

生成或审查原型时，按页面实际使用的控件读取本规范。原生 HTML、组件库、自定义绘制的同类控件采用相同业务要求，不能因为画成 div、图标或文本就省略说明。不新增菜单，也不为凑齐清单添加页面未涉及的能力。

## 写在哪里，怎样算说明清楚

- 规则唯一来源仍为 `requirements[].rule_details`，按需使用 title、statement、clauses、table、examples；interaction.rule_ids 将它们投影到原型标注，PRD 与完整导出共用内容。不要另建一套控件规则数据。
- 每个控件要回答：它表示什么、数据从哪里来、初始是什么、用户怎样改变它、改变后发生什么。只填适用细节；简单控件用一两句，多个选项或分支用表。
- “支持下拉”“支持多选”“默认展示”“选择后联动”不足以交付。写出具体选项与默认项、选择数量限制、触发时机、影响对象和变化结果。未确定的部分给出具体待确认问题，不能凭常见设计习惯补成已确认。
- 原型控件可做展开、选择及必要联动，提交结果仍由预设页面状态展示。完整选项与行为在标注中写清，不要求读者操作后才能发现规则。不同画面中的示例选中值不自动等于产品默认值。
- 默认值、阈值或选项尚未确定却需画示意时，在该控件或字段旁简短标“默认值待确认”等具体说明，关联唯一待决策规则；不能只在页头统计或未选中的侧栏中提示。示意值不作为正式实现/验收预期；已保存值回填与首次默认分别说明。不为已明确的字段重复加免责声明。
- `interactions[].properties` 和 HTML 属性只用于配置/呈现；它们不能代替业务说明。配置的 options、defaultValue、required、min/max 等必须与关联规则一致；不能仅在属性或截图里藏一个约束。

## 重复列表：覆盖规则，不重复编号

先按字段语义与适用行为分组，再登记标注；不要按行号循环给每个相同单元格创建 interaction。

- 同列各行来源、格式、约束相同：在列标题内的文字区域或一个可见代表项标一次，标题说明“名称列（全部行）”等适用范围。不同列即使暂时引用同一规则，也不能仅凭 rule_ids 相同自动合并。
- 同类行内操作条件/结果相同：选一个可见可操作的代表按钮标一次，说明按被点击行的稳定编号作用，不默认只对首行生效。可点击按钮及真实数据仍完整绘制。
- 行的状态、权限、禁用原因、条件或结果不同时，单独保留差异标注；例如启用行的编辑/停用与停用行的禁用说明。不同示例文案、颜色值本身不构成新规则；空值有独立展示规则时，纳入列规则或单独标空值差异。
- 同组实例使用相同 `data-rule-ref` 关联唯一 interaction，每个实例仍有唯一 HTML id，必要元素清单和控件检查仍逐项保留。代表项的 selector 指向本状态内唯一锚点；阅读器只放一个编号并高亮该锚点。代表项被局部筛选/联动隐藏时，阅读器改用同状态内可见的同组实例，仍只放一个编号；全部实例不可见时不悬空显示编号。其他状态的独有差异仍用状态专属 interaction，不借隐藏项或别的状态承载说明。

```html
<!-- interaction: INT-NAME，selector: #name-heading；名称列统一规则 -->
<th><span id="name-heading" data-rule-ref="INT-NAME">名称</span></th>
<td><span id="row-a-name" data-rule-ref="INT-NAME">重点客户</span></td>
<td><span id="row-b-name" data-rule-ref="INT-NAME">试用客户</span></td>
```

共用标注只减少视觉编号与重复维护，不减少实际控件/数据，也不取消对每个实例的默认值、状态和规则适用性核对。状态变化的实例不能误绑统一可操作规则。编号由共享阅读器绘制，不在产品 HTML 内另画常驻圆点。

## 选择类：选项与默认必须明确

固定枚举列出**全部业务选项、总数、展示顺序和默认选择**；选项表有 label 与业务值/含义。已有确定编码时一并写出，接口编码未确定则写待约定，不自行设计接口契约。

“请选择”“全部”“不限”、空值分别说明是占位、查询条件还是实际业务值；数量统计说明是否包括这些特殊项。默认无选择就明确写“默认未选”，不能以占位文案代替默认值说明。

动态选项不能编造固定数量。写清来源、可见范围、排序、过滤/搜索口径与加载方式；按需说明无选项、加载失败、已有选择不再有效时的处理，以及新建默认与编辑回填。若总数随数据变化，明确“数量动态，以符合条件的数据为准”，不把几条样例当完整枚举。

| 控件 | 必须按实际方案说明 |
| --- | --- |
| 单选下拉框、下拉搜索 | 选项及数量/动态来源；默认项/未选；是否必选、可清空；搜索与匹配（若有）；选择何时生效；选后影响哪些字段；依赖变化时保留、清空还是重新选 |
| 多选下拉框、复选框组 | 全部选项/来源；默认选中集合/空集合；最少/最多可选数或明确不限；全选的作用范围；取消、清空、禁用项；已选计数/展示顺序与超限反馈（若涉及） |
| 单个复选框 | 表示的业务含义；默认勾选与否；勾选/取消分别产生什么结果；是否必须同意；何时保存。部分选中状态若存在，说明推导规则，不能把它当第三个独立提交值 |
| 单选框组 | 各选项与总数；默认项或默认未选；组内互斥范围；是否允许恢复未选；必选条件；切换后的内容、校验及数据保留 |
| 开关 | 开/关对应的业务含义；默认状态和回填来源；即时保存还是随表单提交；生效范围；权限/禁用条件；失败时保留或恢复；危险变更确认（若有） |
| 级联、树、穿梭选择 | 各层数据来源与层级；父子选择关系、叶子/节点可选范围；单/多选、数量限制；默认路径/已选值；上级变化后下级值、加载失败及失效值处理 |

以下仅为**写法示例**，业务值不能直接套到真实项目：

| 控件 | 数据与默认 | 行为 |
| --- | --- | --- |
| 订单状态下拉 | 3 个业务选项：待处理、已完成、已取消；另有查询项“全部”，界面共 4 项；默认全部 | 单选且不能清空，切换立即查询并回到第 1 页；其他筛选条件保留 |
| 通知方式复选框组 | 2 项：站内信、邮件；默认仅站内信 | 至少 1 项、最多 2 项；不能取消最后一项，原位置提示“至少选择一种通知方式”；随表单提交 |
| 配送方式单选框组 | 2 项：自提、配送；默认自提 | 切换为配送时显示必填地址；切回自提清空地址，本次提交不携带地址 |

示例中的取舍需真实方案支持。若产品未决定切换后地址是否清空，应在规则中明确该问题，而不是按示例生成。

## 输入、操作与展示类

| 控件或元素 | 按适用性说明的数据与交互 |
| --- | --- |
| 文本框、多行文本、富文本、密码 | 字段含义/来源、默认/回填、必填、长度与计数口径、空白/格式处理、允许内容；校验时机与反馈；清空、计数、显示密码等小操作。富文本涉及格式、粘贴、图片时说明实际支持范围 |
| 数字输入、步进器、滑块 | 数值含义、单位、默认/空值、上下界及包含关系、精度/步长、键入与步进限制、越界反馈；范围选择说明两端约束；派生值何时重新计算 |
| 日期、时间、区间选择 | 业务时区、格式、默认与回填、可选范围、边界包含关系、粒度、禁选条件、起止约束；快捷项的实际范围；清空和日期跨日处理（若涉及） |
| 文件、图片、附件上传 | 类型、数量、单个/总大小、默认已有附件、上传时机；重复文件、失败重试、删除/替换、预览/下载与保存结果。未规定的限制待确认，不擅自给数值 |
| 按钮、链接、图标操作、菜单项 | 操作对象、显示/可用条件、点击结果与目标；是否确认、处理中及重复操作；成功/失败反馈、返回与未保存内容。图标有明确业务名称，不能只标“按钮” |
| 搜索、清空、重置 | 搜索字段与匹配方式、输入触发/回车/按钮触发、防抖时机（有确定约定时）；清空与重置分别恢复什么；是否立即查询、分页/排序是否重置 |
| 标签页、分段选择、折叠区 | 项目及顺序、默认激活/展开项、切换条件；数据何时加载；切换时输入、筛选、滚动和选择是否保留；数量徽标口径（若有） |
| 表格、列表、行选择、分页、排序 | 字段含义/来源/格式/空值、默认排序与同值顺序；行操作条件；跨页选择、全选范围和失效记录；默认页大小、可选大小、总数口径；筛选/排序后页码和已选项处理 |
| 弹窗、抽屉、提示、工具提示 | 触发与关闭方式、默认内容和焦点（影响操作时）；确认/取消/遮罩/关闭图标的结果；输入保留、可否关闭；提示触发、文案、位置、持续/消失条件。悬停提示的业务含义也应直接标注 |
| 只读字段、标签、徽标、结果、统计值 | 含义、来源/范围/计算口径、单位/精度/时间、枚举映射、空值/未知/脱敏/截断、可点击时的行为；样例数值与真实计算规则区分 |
| 图片、音视频、画布、地图、颜色选择等专用控件 | 明确本次承担的业务任务、数据来源、初始内容、支持操作及结果；如涉及播放、标点、裁剪、缩放或颜色值，说明实际范围与失败处理。不要为了 HTML 标签齐全强造专用能力 |

隐藏字段、技术属性、纯装饰元素不强行放置视觉编号；影响业务提交、校验或数据口径时，在关联业务规则中说明。组合控件可共用一条说明，但独立的小操作、不同约束或不同结果必须能精确定位。

## 规则与画面

按 [local-controls.md](local-controls.md) 区分页面状态和局部交互，按 [prototype.md](prototype.md) 组织画面与标注。控件规则需要可查看的 UI 或操作路径，不能只用文字替代必要元素和反馈位置；不为所有取值组合重复整页。

## 生成后的逐控件复核

1. 按状态遍历实际画面和必要元素清单，识别控件类型；对照本表选适用项，包含小图标、清空、关闭、重置、行内操作及关键只读数据。
2. 对每个选择类控件核对选项来源/数量、完整范围和默认选择；多选核对数量和全选范围，单选核对互斥和未选状态。固定枚举逐项核对画面、HTML 配置与规则，动态来源核对过滤与失效处理。
3. 区分首次进入、编辑回填、状态切换、失败恢复和返回重入；只记录实际有差异的值和行为，不为每个控件机械增加画面。
4. 逐个点击控件标注，核对其在当前状态下关联的取值/默认/约束、禁用或联动结果及必要恢复都能一起读到；状态专属原因先于通用约束。操作标注还要沿关联入口核对实际适用的成功、失败、未知与恢复分支；缺少引用时补到唯一规则源，不把整个功能全部绑定。只关联某一条规则或比对 rule_ids 一致不能代表完整。
5. 核对每个元素标注引用的规则确实解释了该控件，而非仅有引用或整表单泛化描述。将缺项补入唯一规则源，待决策写明影响；不要求开发根据原型自行推断。

现有自动检查能发现必要元素缺少精确标注、规则关联或表结构错误；**不能自动证明所有 HTML 控件都被识别，也不能证明选项、默认值或行为已经写全**。上述逐控件语义复核是交付步骤，不能用结构检查通过替代。
