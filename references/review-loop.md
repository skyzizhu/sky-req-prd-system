# 评审批注处理闭环

用户要求处理原型反馈、采纳批注或核对整改完成情况时读取。批注是评审意见，正式需求仍在 spec/源文档；处理状态不等于 PRD 已经同步或真实产品通过验收。

## 原型内处理

点击已保存标记仍默认只读查看；点击“处理批注”才进入处理表单。状态为 pending 待处理、accepted 已采纳、rejected 已驳回、completed 已完成。

- 待处理 → 采纳/驳回；采纳 → 完成/驳回/待处理。
- 已完成或已驳回需要重新处理时先回到待处理。
- 非待处理状态必须填写处理说明。采纳/完成必须关联当前页已有 FR ID；完成还需正式修改记录 ID 和验证说明。
- 处理说明、关联需求、修改记录及验证说明在查看卡片展示；最近 30 次处理变化保留本机时间和说明。不是多用户身份审计，也不证明填写内容真实。
- 修改批注正文或优先级会重新标为待处理，清除当前完成引用/验证说明，保留状态变化历史。隐藏/删除标记不等于处理完成，恢复后仍保留处理记录。撤销可恢复最近操作。
- 管理面板按处理状态筛选，导出仍包含本页全部批注（含隐藏项与处理历史），不是只导出筛选结果。

## 正式采纳流程

用户决定采纳后，读取导出的批注文件、需求和现有 impact；按用户意图修改正式 PRD、关联原型及验收。使用 editing.md 的保存命令后取得 undo_id（32 位保存记录 ID），作为 change_ref 填回批注。完成关键路径验证后填写验证说明再标完成。人工外部修改可以填写对应记录标识，但自动核对工具不会将其认作已核实的本地保存记录。

```bash
python3 <skill>/scripts/review_notes.py <项目目录> <导出的批注.json>
```

工具只读核对项目/版本/页面、FR 关联，以及 change_ref 是否对应 `.editing/<ID>.json` 中该版本、覆盖关联需求的 saved 记录。输出 change_record_verified 和缺口。此核对只证明记录关联，不证明当前实现仍与那次保存相同，更不证明验证说明对应真实产品测试。跨版本整改或外部工单由 Agent 对照具体版本和记录人工核实，不能强行改导出文件的项目/版本字段绕过检查。

## 存储与兼容

批注仍按项目/版本/页面存在当前浏览器 localStorage，可导出/导入迁移；没有自动多人同步。新导出 schema_version=2，含 reviews 数组；新 runtime 接受旧 schema_version=1 并默认为待处理。旧 runtime 会拒绝新版文件，避免静默丢失处理历史。冻结版本资源不自动更新；需要新功能时在规划版本升级。正式需求文件和冻结快照不因批注处理而改变。
