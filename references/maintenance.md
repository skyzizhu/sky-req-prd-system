# 轻量维护入口

用户修改已生成项目时只走本入口，不执行首次生成流程，不要求重读全部 references。先定位项目和版本，读取项目 config.md 的适用约束。自然语言由当前 Agent 理解，以下脚本不调用模型，也不会新建项目或版本。

先读取 `.skill-lock.json`，按其中 runtime 打开对应 SKILL.md/本文件并使用同版工具。安装新版不会自动升级已有项目；CLI 会校验并路由到锁定副本，损坏或缺失时停止写入。无锁的现有 V2 先只读检查，明确采用版本后按 [production-delivery.md](production-delivery.md) 升级，不猜测原生成版本。

1. 输入可以是“通知设置里的重复推送规则改一下”“这个原型页面加一个字段”或整页改版；从用户给出的路径/链接及工作区定位原项目，不要求重新提供整套方案。HTTP链接先映射本地源目录，不从展示页重建。
2. `python3 <skill>/scripts/maintain.py '<本地项目或HTML深链接>' --version v1.1 --query '名称或编号'` 返回至多 50 项精简索引、版本状态及 revision。用 --key 精确读取一个文档/小节；结构化规则/控件用 revise_item.py 定位。远程网页必须先映射已有本地源目录。
3. 小节、埋点事件、测试用例、风险、里程碑、表格行使用明确、稳定的 `<!-- material: RISK-001 -->` 锚点，范围到下一个锚点前。重命名不改 ID。不要在 Markdown 表格内部插入注释打断表格；表格整体设置锚点，行使用第一列稳定 ID，再用唯一原文替换目标行。旧文档没有锚点时仍可按文件+唯一原文修改，不为一次小改重写所有文件补编号。
4. Markdown 局部补丁文件格式：`{"source":"prd/risks.md","anchor":"RISK-001","before":"原文","after":"修改后"}`。anchor 可省略；before 必须唯一匹配。`maintain.py <项目> --version v1.1 --patch <补丁.json> --revision <指纹>` 预览，加 --save 保存。写补丁使用 apply_patch。冲突/重复原文/冻结版拒绝覆盖，输出影响和撤销 ID，不返回整套物料。
5. 单规则/控件属性读取 incremental.md 的单字段入口；多项关联规则一次修改包读取 editing.md。布局/预设状态按 selector 局部 apply_patch，读取受影响依赖及 prototype.md 的相关约束，不能改编译产物。新增功能或跨页面重大改变才进入范围规划。
6. 文字修订检查目标差异与引用；业务规则变动复核关联 PRD、预设画面、局部交互声明、提示和测试。运行 build/validate，按风险验证相关浏览器路径。Markdown 无结构化依赖时影响报告仍保守列全部页面，不误称已实现精准依赖分析。构建是程序编译，不让模型重写未变物料。

表格第一列已有稳定编号（如 EVT-001、TC-001、RISK-001）时自动登记 row 定位键；--key 返回该行，可用唯一原文补丁修改单个单元格或该行。索引读取和保存器在程序内部可能仍检查全项目，模型只接收候选/选中内容；不承诺已实现文件级增量编译或量化 token 降幅。

站点顶部“定位并交给 Agent”可选择索引中的物料，复制项目标识、版本、来源、编号与当前链接。此功能不向外部发送内容，不绑定某种 Agent，也不保证远程链接可以直接写回源目录。项目总览、交接汇总等派生节点只定位，不直接改汇总 HTML；应修改其 project.json/spec/文档/台账来源。附件元数据定位后沿用附件追加流程，不用正文补丁替换二进制。

原型入口优先定位当前选中的标注，并带上页面、状态、控件编号/源选择器、关联需求/规则和可重开的目标链接。无法读取当前画面时明确退回页面级定位，不从旧链接猜测。功能正文按当前阅读需求或具体验收定位；多源章节/未匹配目标要求手动选择，不能静默选第一项。用户复制上下文后补充“控件名称、改前→改后、适用状态/范围”，如“首次未保存设置时，推送频率默认由实时改为每日；已有设置仍回显”。Agent核对源内容和指纹后再修改；截图/展示值不自动视为真实默认值，冻结上下文也不能自动改写其他规划版本。

## 维护范围与最小上下文

| 请求 | 读取与修改范围 |
| --- | --- |
| 单条规则/文案 | 精确叶字段；仅补必要的关联规则、验收、目标状态 |
| 单控件 | 该控件标注、规则及所在状态HTML/CSS片段；共享行为改变再扩相关状态 |
| 整个页面 | 该页HTML/CSS、状态/元素/标注及必要规则；其他页面保持，公共CSS变动时复查调用页 |

先用maintain的精简索引，或revise_item的--summary搜索；再--read读取指定规则/叶字段，具体命令见incremental.md。不为小改加载完整PRD、所有状态截图或整套spec到模型上下文。校验器内部仍可能扫描全项目，build也可能重编译完整展示数据；这不等于模型重新生成全文，不承诺所有改动都只编译一个文件。

整页布局修订可以重做该页，但须保留其业务规则、必要元素和稳定ID；用户明确删除/改规则时再同步修改对应源数据。先预览差异/impact，再验证本次相关路径，最后checkpoint并按workflow.md回报两个地址及打包目录。冲突或缺源文件时说明具体缺失，不以“重新跑技能”作为修复手段。

共用规则正文变化时，按shared_rule_ids复核引用功能的规则、验收、页面及图；功能清单和交付索引应反映其生效约束变化，不能仅因引用ID没变仍标“沿用”。只作关联阅读的related_rule_ids不自动继承业务变更；未结构化文字引用仍须按关键字人工反查。

修改共用标注时先区分组规则与单条示例：组规则修改指向唯一interaction/rule；只改某行数据或元素须说明稳定行编号及目标状态，不把示例值变动误应用到全列。画面内临时回退的代表项仍指向同组规则，不代表业务对象身份改变。
