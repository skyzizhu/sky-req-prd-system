# 开发交接视图与任务包

用户要求交付给开发、导出任务或按开发关注点查看范围时读取。固定入口左侧“开发交接与任务包”进入 `#/v/<版本>/_delivery/tasks`。交接修订从其报告页进入，链接保持快照版本，不自动切换当前依据。

工作版与 current_handoff（没有则 base）比较；交接快照与其固定 base 比较。界面明确工作草稿/冻结物料、比较基线与项目当前开发依据。

每条需求输出：新增/修改/移除/关联变化需复核、来源需求确认状态及阻塞属性、完整规则/实例、控件动作及属性、验收、需求/原型链接、分工与依赖。移除条目保留旧版链接和验收；需求子规则 pending 不能被父需求 confirmed 掩盖。确认只代表文档记录，不能自动宣称技术评审或真实测试通过。

有明确分工及依赖资料时，为需求填写可选字段：

```json
{"delivery":{"roles":["frontend","backend","qa"],"dependencies":["依赖订单状态查询接口；负责人和交付时间待确认"]}}
```

没有依据时不编造。缺分工时各角色筛选均保留并标待分工；空依赖展示“未登记，需评审”，不是无依赖。前端/后端/测试仅为关注方向，不是自动拆好的工时或实施方案。

支持关键词、仅本次变化、待确认、阻塞与角色筛选，导出当前筛选的 Markdown/JSON。任务包来自与界面相同的数据，包含版本、基线和链接；不调用外部任务系统、不代替创建工单。file:// 导出的链接只在对应机器路径有效；团队分享应使用固定托管地址再导出，不能宣称本地路径是团队可用链接。

比较包含需求、交互与页面关联。共享代码、样式或正文变化无法自动确定业务影响时，保守将相关版本需求列为需复核，并在导出记录 changed_files；不以文件未变证明业务正确。缺旧 content_hashes 的旧构建需重建外壳数据，不能改写冻结内容。该模块只增加编译数据与外壳视图，不写历史物料。
