# sky-req-prd-system

> req / PRD in → **Product System** out
> 把散落的需求，变成一份能看、能改、能追溯的产品方案。

[![skill](https://img.shields.io/badge/Agent%20Skill-SKILL.md-blue)](https://agentskills.io) [![license](https://img.shields.io/badge/License-MIT-green)](./LICENSE) ![agents](https://img.shields.io/badge/%E5%85%BC%E5%AE%B9-7%20Agents%20%7C%20ZCode%20%7C%20Claude%20%7C%20Codex%20%7C%20Gemini%20%7C%20OpenClaw%20%7C%20Cursor%20%7C%20WorkBuddy-green)

**一句话**：这是给产品经理的 AI 工作流 skill。对它说「**帮我出具详细的产品需求方案：xxx**」或「**帮我出具详细的产品设计方案：xxx**」（xxx 为你的产品描述），把 PRD 文档、半成品需求甚至几句零散描述交给它，它生成一个完整的**产品方案 HTML 站点**，包含：产品需求文档、整体流程图 / 泳道图 / 状态图、信息架构、低保真原型、测试与上线目标——纯本地生成、双击即开、可持续迭代修订。

## 它解决产品经理的什么痛点

| PM 的日常困境 | sky-req-prd-system 的答案 |
|---|---|
| 需求散落在聊天记录、会议纪要、脑子里，永远凑不成一份完整文档 | 扔进来就行：AI 按标准 PRD 骨架（11 个固定节点 + 15 个条件节点）整理成结构化站点 |
| PRD 模板太重，写完即过时，没人愿意维护 | 产物是**活文档**：说一句“把回收站改成 3 天”，只增量更新对应页面，永不整站重生成 |
| AI 生成的内容不敢直接用——分不清哪些是真需求哪些是编的 | **全面溯源**：每个页面带徽标（PRD 原文 / AI 推断 × 已确认 / 待确认），“待确认清单”自动聚合，评审时逐条勾 |
| 原型图和需求文档两张皮，交互说明堆成一团 | 低保真线框 + **连线式四色标注**（红=核心、黄=待确认、蓝=说明、绿=参考），序号徽章指哪说哪，连线永不交叉 |
| 评审会上翻几十个文档找上下文 | 一个站点：左菜单右详情；投屏「待确认清单」页，从上往下过 |
| 换个 AI 工具就得重来一套 | SKILL.md 遵循开放规范，一条命令装到 ZCode / Claude Code / Codex / Gemini / OpenClaw / Cursor / WorkBuddy |

## 它能生成什么

一个纯本地、零依赖、**双击 index.html 就能打开**的静态站点：

```
product-system/
├── content/                   # 内容层（AI 生成/维护的唯一部分）
│   ├── manifest.json          # 结构唯一事实源
│   ├── overview/              # 产品概览：定位、商业/用户目标、北极星、竞品、版本记录
│   ├── requirements/          # 需求文档：功能清单、FR 详述、用户故事、非功能、
│   │                          #   风险依赖、名词解释 + 流程/泳道/状态图（Mermaid）
│   ├── info-structure/        # 信息结构图（HTML/CSS 卡片树）
│   ├── prototype/             # 低保真线框原型：按产品形态选画布，序号徽章四色标注
│   ├── testing/               # 验收标准（Given/When/Then）、测试用例
│   └── launch/                # 上线目标、里程碑、Checklist、数据埋点
└── site/                      # 展示外壳（一次安装，基本不动）
    └── index.html             # ← 双击这里
```

站点自带：模块折叠菜单（页面自动带 01· 序号）、溯源徽标、待确认聚合页、Mermaid 渲染（断网降级源码）、原型 iframe 预览。

## 怎么用

### 第一步：让 agent 认出你的 skill

skill 安装后（见上文），在**新会话**中说以下任一类话术即可触发，无需任何配置：

| 场景 | 示例话术（直接复制改写） |
|---|---|
| 提供信息后整体生成 | 「以上是我的所有产品信息，帮我生成详细的产品方案。」 |
| 出具需求方案 | 「帮我出具详细的产品需求方案：健身打卡 App，用户每天记录运动、分享给朋友。」 |
| 出具设计方案 | 「帮我出具详细的产品设计方案：xxx（产品描述）」 |
| 整理已有 PRD | 「把这份 PRD 整理成产品方案：…（粘贴内容或附文档路径）」 |
| 从代码反推文档 | 「从代码里把拖拽功能整理成需求文档页面」 |
| 增量更新方案 | 「把回收站保留期改成 3 天，另外加一个排行榜页面」 |
| 评审状态流转 | 「快速粘贴这块需求确认了」「把风险与依赖、名词解释也都确认了」 |

若自动触发未命中，可显式调用：

- **ZCode / Claude Code**：输入 `/sky-req-prd-system`，或说「用 sky-req-prd-system 处理」
- **Codex / Gemini CLI / Cursor / OpenClaw / WorkBuddy**：对话中点名「使用 sky-req-prd-system 这个 skill」

### 💡 输入越完整，输出越贴合预期

**建议尽量提供完整的需求信息**，生成效果会显著更好、更符合设计方案的预期。一份信息充分的输入通常包含：

- 产品名称与一句话定位、建设背景
- 目标用户与角色划分（如群众 / 经办 / 审批 / 管理员）
- 核心功能清单（尽量带优先级与关键规则数字）
- 端与形态（Web / App / 小程序 / 大屏…，单端还是多端）
- 非功能要求（性能、合规、安全等）与里程碑
- 明确的边界（一期做什么、不做什么）

信息不足时 skill 会**分级追问**或**类比补全**（标注「AI 推断 / 待确认」），但一手信息永远比推断准确——补全比例越高，评审成本越高。

### 触发边界（不是所有场景都会触发）

**触发**：同时满足「提供了产品信息」+「明确要方案交付物」两个条件。\n**不触发**：单纯讨论/分析需求、要单份普通文档、技术/运营方案、写代码改代码、问用法。\n**模糊时**：会先问你「要完整方案站点，还是只是讨论？」——一次确认远比误触发划算。

### 第二步：按引导对话（一次完整流）

```
你：帮我出具详细的产品需求方案：健身打卡应用，用户每天记录运动、分享给朋友。
AI：（贫瘠输入 → 批量问 3~4 个骨架问题：形态？范围？阶段？目标？）
你：mobile App，全量，0→1 新品，目标是次月留存 35%
AI：（归纳清单确认 → 生成全部页面 → 构建+校验）
AI：✅ 产品方案已更新
    入口文件：/Users/xx/ps-test/product-system/site/index.html（双击打开）
    本次变更：新增 23 个页面…  待确认：12 项

你：把打卡积分上限改成每天 50 分，再加一个排行榜页面
AI：（增量更新：只动相关文件 → 变更清单 → 交付报告）

你：快速粘贴这块需求确认了
AI：（状态翻转 → 徽标与待确认清单同步更新）
```

### ⭐ 个性化配置（推荐设置一次，所有产品生效）

复制 `config.example.md` 为 `config.md`，把**你的**理念与约束沉淀进去，之后每次生成都自动遵守：

```bash
cp ~/.agents/skills/sky-req-prd-system/config.example.md \
   ~/.agents/skills/sky-req-prd-system/config.md   # 全局（所有产品）
# 或放到某个方案目录下：product-system/config.md   # 仅该产品，优先级更高
```

可配置六类内容：

| 小节 | 作用 | 示例 |
|---|---|---|
| 产品理念 | 影响需求取舍与方案气质 | 「工具极简，能用系统默认不自研」 |
| 设计理念 | 影响原型取向与交互规范 | 「移动端单手完成主流程」 |
| 输出风格 | 详略（简洁/标准/详尽）、文风、术语习惯 | 「统一用『用户』不用『客户』」 |
| **输出物约束** | **硬约束，逐条强制遵守** | 「P0 必附验收口径」「禁用词：赋能、抓手」 |
| 溯源政策 | AI 推断标注的容忍度 | 「保守：无依据一律标待确认」 |
| 默认偏好 | 预填形态/受众，减少追问 | 「mobile / c」 |

规则：无 config.md 完全按默认流程；有则必须先读取并遵守；**质量底线（溯源、增量、验证）不可被配置覆盖**。详见 SKILL.md「用户配置」节。

### 行为约定（触发后 agent 会怎样做）

- **先问后写**：贫瘠输入会先批量问骨架问题（形态/范围/阶段/目标）；信息充分则直接出归纳清单
- **先确认后生成**：展示将生成的模块与页面清单，你点头才动手
- **只改该改的**：增量更新，绝不整站重生成；覆盖你手改过的内容前会先确认
- **验证后交付**：跑 `build.py` + `validate.py`（退出码驱动），报告入口文件绝对路径、变更清单、待确认数
- **说不给了就不问**：声明「没有更多信息」后转入类比自补全，全部标注 ai-inferred 待确认

## 五阶段工作流

```
定位（初始化 or 增量）→ 输入解析（形态必判·分级追问·拒绝时类比自补全）
→ 归纳确认（冲突六查·变更清单）→ 生成/更新（manifest 先行·人工修改保护）
→ 构建验证（build.py + validate.py 退出码驱动）→ 交付报告（入口路径·变更·待确认数）
```

核心机制：内容与站点分离 · manifest 唯一事实源 · 增量更新 · 全面溯源 · file:// 直开 · validate.py 不带病交付。

## 安装

SKILL.md 格式遵循开放规范（[agentskills.io](https://agentskills.io)），各主流 agent 均可直接使用，差异仅在发现路径：

```bash
git clone https://github.com/skyzizhu/sky-req-prd-system.git \
  ~/.agents/skills/sky-req-prd-system
```

多 agent 共存时一键安装（symlink 到各家目录，未安装的自动跳过）：

```bash
bash ~/.agents/skills/sky-req-prd-system/scripts/install.sh          # 链接（推荐）
bash ~/.agents/skills/sky-req-prd-system/scripts/install.sh --copy   # 或复制
```

## 设计原则

1. 内容与站点分离：只生成 `content/`，外壳一次安装基本不动
2. manifest 唯一事实源：结构变更先改 manifest
3. 增量更新 + 人工修改保护：产物是活文档，不是一次性输出
4. 全面溯源：AI 补全永远可见、可评审，杜绝“AI 编的需求混进真需求”
5. 多端支持：C 端 App + 管理后台等组合，原型按端分组
6. 确定性验证：validate.py 一键校验，不带病交付
7. 零依赖：纯静态 + Python 标准库构建，file:// 双击直开

## 更新日志

### 术语与话术
- 「产品系统」统一更名「**产品方案**」，交付物表述为「产品方案 HTML 站点」
- 触发话术支持：「帮我出具详细的产品需求方案：xxx」「帮我出具详细的产品设计方案：xxx」「以上是我的所有产品信息，帮我生成详细的产品方案」

### 输入与追问
- **分级追问**：按输入充分度分档（充分不问 / 中等 ≤2 问 / 贫瘠批量问 3~4 个），只问骨架级问题（形态、多端、本次范围、产品阶段、成功标准）
- **拒绝追问时类比自补全**：用户声明无更多信息时，基于同品类通用模式关联补全（可结合 WebSearch），全部标 ai-inferred/pending
- **受众端型 `audience`（c/b/g）**：C 端 / B 端 / G 端三档，决定目标写法、条件节点倾向（B端→权限必查、G端→合规必查）、非功能侧重、原型取向
- 输入源支持：PRD 文件 / 粘贴内容 / 零散需求 / **代码库**（从实现反推文档，source=origin）

### 结构与节点
- 标准 PRD 骨架：11 个固定节点 + 15+ 条件节点（数据埋点、时序图、权限角色、交互规范、国际化、灰度 AB、发布渠道等）
- **多端支持** `product.ends`：C 端 App + 管理后台等组合，原型按端分组，功能清单加端列
- 功能需求强制「**异常与边界**」小节；版本演进约定（bump 时机与版本记录自动追加）
- **需求文档连续长页** `layout: continuous`：全部二级页拼为长页，菜单=锚点平滑滚动，滚动时菜单高亮/面包屑反向联动（scrollspy）

### 原型与标注
- 六种产品形态画布（web / desktop / mobile / h5 / miniapp / tv）
- **连线式四色标注**：红（核心）> 黄（待确认）> 蓝（说明）> 绿（参考），标注栏顶部图例
- **序号徽章**：目标点为带序号的圆形徽章，序号兼作标注框前缀，连线永不交叉
- 线框页菜单自动带 `01 ·` 序号；页面总览内置「标注阅读说明」（四色表 + 读图方法 + 约定）

### 站点体验
- 一级菜单**默认折叠**，当前路由模块自动展开，用户选择 localStorage 记忆
- 侧栏整体**收起/展开**按钮（品牌区「⟨」/ 左上角「☰」浮钮），状态记忆
- Markdown **图片支持**：素材统一放 `content/assets/`，`![]()` 自动补路径前缀
- file:// 双击直开（build.py 编译 data.js，无 fetch / ES modules）；资源版本参数防 HTTP 缓存

### 质量与验证
- **validate.py 确定性校验**：manifest 结构与枚举、id 规范与唯一性、file 引用存在性、HTML 零内联、data.js 新鲜度、**孤儿文件警告**、**已确认页残留待确认块警告**（退出码驱动）
- 结构变更前 manifest 自动备份；人工修改保护（覆盖前 diff 确认）
- 归纳阶段**冲突六查**：数字冲突 / 功能重复 / 优先级矛盾 / 已确认冲突 / 形态冲突 / 端归属
- 内容深度基准：FR 每模块 5~15 行、场景 2~4 个、每页标注 3~5 条、Mermaid 单图 ≤15 节点
- macOS 交付自动 `open` 入口文件；交付报告固定格式（入口绝对路径 + 变更清单 + 待确认统计）

### 跨 Agent 兼容
- SKILL.md 遵循 agentskills.io 开放规范，兼容 **7 家 agent**：ZCode / Claude Code / Codex / Gemini / OpenClaw / Cursor / WorkBuddy
- `scripts/install.sh` 一键安装（symlink / 复制，未安装自动跳过，防自链接）
- SKILL.md 工具名解耦（不绑定特定 agent 的交互工具）

### 协作
- 交付报告含双地址：本地入口路径 + 局域网共享地址（serve.py 自动探测本机 IP）
- 分享三方式：局域网即时评审（serve.py）/ 压缩目录离线发送 / git 长期协作
