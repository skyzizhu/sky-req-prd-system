# 按交付场景选择物料

项目总览与版本计划由项目壳提供。每版第一项为“本版概览与变更”：问题、用户、目标、范围、排除项、与上一版的变化、待决策和影响面。

## 场景裁剪

| 场景 | 应交付 |
|---|---|
| 新项目首版 | 定位与范围、关键需求、页面与流程、交互原型、验收、上线条件 |
| 已有项目增加功能 | 本次差异、受影响需求与页面、必要流程、增量验收及上线影响；其余继承 |
| 用户明确指定交付物（只要 PRD / 只原型 / 只要流程或用例） | 仅生成所指模块；只要原型仍需最小 spec（规则来源与需求面板依赖），但不产出文档页；其余模块后续可增量补齐 |
| 当前版规则修订 | 更新同一版本的需求及关联原型/测试，交付影响清单 |
| 原型交互专题 | 页面级结构化需求、交互闭环、异常演示与验收；不强制扩写竞品或商业计划 |
| 历史查阅 | 使用已有快照，不生成新物料 |

不按固定页数、FR 行数、标注数量验收。以本次问题是否说清、关键流程是否可操作、开发是否能查到规则判断完整度。

按需裁剪是省 token 的正当手段，不是偷工减料：用户点名要什么就只出什么，并在归纳清单写明「本次仅出 X，未出 Y（可后续补）」；没点名就按上表全量裁剪。禁止在点名子集时顺手补全其他模块，也禁止把「没出的模块」当成「不存在」。

## 本版常用模块

- 概览：本次变化、排除项、依赖与决策。
- 需求：功能索引、spec 生成的页面需求与验收；必要的跨页业务规则、权限矩阵、数据口径。
- 原型：本版页面目录、主要流程的可交互页面；真实用户会遇到的空/加载/错误/权限及提交状态。
- 验收与测试：复用 spec 的 AC，不复制第二份口径；补充跨页正常路径、异常与回归步骤。
- 上线：放量条件、指标口径、失败后的处理方式；真实负责人或阈值未知时标待确认。

## 按信号纳入

多角色协作 → 泳道图及权限规则；实体生命周期复杂 → 状态图；接口协作 → 必要接口/时序说明；多层导航 → 信息架构；指标变化 → 埋点与观察口径；金融/医疗等敏感业务 → 根据实际范围确认合规要求；增长实验 → 实验假设和分组。

图表帮助解释流程时才使用，纯展示或单项配置不硬造图。大的图拆为可读的子流程，不用节点数量替代业务判断。

## 端与受众

form 为 web/desktop/mobile/h5/miniapp/tv；多端使用 ends 并按端组织原型，需求索引标明端归属。

C 端关注首次使用、关键任务及留存体验；B 端关注角色、效率、批量操作、权限、审计和系统协作；G 端根据实际业务关注审批职责、留痕和环境约束。不能仅依据受众标签捏造强制要求。
