# sky-req-prd-system · 1.1

> **一句话**：把产品经理手里零散的产品需求，变成开发直接能用的完整交付物——结构化需求文档、可交互原型、测试用例、上线计划，沉淀为一个长期维护、变更可追溯的项目站点。

## 在 Agent 中怎么用（案例）

本技能由 Agent（ZCode / Claude Code 等）加载执行。你用自然语言说需求，Agent 负责定位项目、结构化、生成、验证与交付——以下是七个真实工作流案例。

### 案例 1 · 零散需求 → 完整首版

> 你说：「做一个倒计时 Web 小组件：预设和自定义时长、启停重置、键盘操作、到时声光提醒，要美观、操作便捷。先要 PRD 和可交互原型。」

Agent 会：初始化项目 → 把散点需求结构化为 spec（每条需求带细粒度规则、实例、GWT 验收；边界与异常自动补充，标注「AI 推断 + 待确认」）→ 生成九章 PRD 与可交互原型 → 浏览器实测关键路径后交付固定入口链接。待确认项集中在「本版变更与待确认」，等你逐条拍板。

### 案例 2 · 只要部分物料（裁剪）

> 你说：「会员积分规则，只要 PRD 文档。」

Agent 只生成需求文档模块，其余不占菜单；概览列明未出项。后续说「补上测试 / 补上原型」即可增量添加。

### 案例 3 · 修改一条规则（自动联动）

> 你说：「把订单名称上限改成 60 字，同步原型、校验和验收。」

Agent 跑 impact 列出受影响页面、控件与验收 → 修改 spec 与原型校验 → 更新用例 → 构建校验后交付。历史版本快照不受影响。

### 案例 4 · 原型评审与批注

你在固定入口打开原型：**查看说明**模式下带规则的控件虚线现形，点击直达规则与验收；**编辑标记**就地新增批注（优先级+说明）。批注可导出 JSON 交回 Agent，核对后采纳进 PRD（处理全程留痕）。

### 案例 5 · 交付开发

> 你说：「交接给开发，冻结当前版本。」

Agent 冻结交接快照 r1（不可变、旧链接永不漂移）→ 「需求范围与交接」按阻塞/关注方向筛选导出清单 → 「复现链接」把指定角色与异常状态发给开发复现。

### 案例 6 · 验收登记与复盘

> 你说：「TC-001 在 Chrome 通过了，截图在这；TC-006 失败，原因是通知权限。」

Agent 整理并入库验收台账（环境 / 构建 / 执行人 / 证据），失败项可转「下一版跟进」；指标观测（基线/目标/实际）同表登记。

### 案例 7 · 下一版迭代

> 你说：「v0.2 增加导出 Excel，沿用当前入口。」

Agent 继承当前物料作为基线只改变化；旧版快照不动，随时对比差异。

**两条协作约定**：① 需求可以很散——Agent 会适当挖掘补细颗粒度（标「AI 推断 + 待确认」，评审转正），业务决策仍由你拍板；② 技能仓库与项目内容分开管理，项目目录建议初始化 git 留痕。

## 这个技能是干什么的

输入通常是**产品经理已经转换过的零散产品需求**（不是用户原话）——可能是几段描述、一份草稿、几条待办。这个技能把它们整理为：

- **需求文档（PRD）**：九章标准结构，每条需求带细粒度规则、实例、Given/When/Then 验收、控件级关联——细颗粒度到开发可以独立开发、独立验收；
- **可交互原型**：不是静态示意图——页面真实可操作（输入、提交、筛选、场景切换），每个控件可点击定位到它的规则与验收；
- **测试用例**：按功能模块分组，与验收口径一一映射；
- **上线计划**：前置条件、观察指标、回退方式。

输入过于简洁或泛化时，技能会**适当挖掘补充细颗粒度**（边界、异常、状态转换、验收实例）——小颗粒度不可能都由产品经理输出，挖掘是职责而非越权；挖出来的内容全部标注「AI 推断 + 待确认」，评审转正；业务决策（阈值、方案取舍、优先级）仍留给产品经理拍板。

## 目标

1. **省掉重复劳动**：需求文档、原型、测试用例的结构化与排版工作由技能完成，产品经理只负责判断与拍板；
2. **口径唯一**：需求、原型、验收、交接共用同一份 spec——不再出现「文档说 A、原型做 B、验收写 C」；
3. **变更可追溯**：改一条规则，影响面（关联页面、控件、验收）自动列出；历史版本冻结快照，随时对比差异；
4. **开发直接用**：开发在同一入口看本版范围、可操作原型、每条规则与验收；复现链接可指定角色与异常状态。

## 解决产品经理的什么痛点

| 痛点 | 技能的解法 |
|---|---|
| 需求文档反复排版、格式劳动 | 需求写进 spec，文档由 spec 编译生成（含自动功能清单表） |
| 原型只是静态图，开发还要追问交互 | 可交互原型 + 每控件关联规则与验收，点击控件直达 |
| 文档、原型、验收三处口径不一致 | spec 是唯一规则来源，三处同源编译 |
| 改了一条需求，不知道影响哪里 | impact 命令列出受影响页面、控件、验收与规则差异 |
| 历史版本和最新版混在一起 | 版本快照 + 交接修订，旧链接永不漂移 |
| 待确认事项散落在聊天记录里 | 「本版变更与待确认」集中呈现，编辑器内逐条确认 |
| 验收执行没有留存 | 验收台账记录环境、构建、执行人、证据，与验收条目关联 |
| 给开发的交接靠口头 | 需求范围与交接视图，筛选导出 Markdown/JSON |

## 快速开始（3 分钟）

环境：Python 3.9+；浏览器用现代 Chrome、Edge 或 Safari。核心页面本地脚本可 file:// 打开；Mermaid 图表走 CDN，断网降级为源码。

```bash
# 生成一个示例项目（含已发布 V1.0 与规划 V1.1）
python3 scripts/create_demo.py /绝对路径/空的示例目录
```

双击示例目录的 `site/index.html`：创建订单 → 查阅详情 → 返回列表 → 批量完成；可切换空态、加载、失败、权限四种场景；打开「本页需求」面板并拖拽停靠；「查看说明」模式下点击带虚线框的控件，直接定位它的规则与验收。示例需求是合成数据，confirmed 仅为测试冻结能力。

安装本技能：

```bash
git clone https://github.com/skyzizhu/sky-req-prd-system.git ~/.agents/skills/sky-req-prd-system
bash ~/.agents/skills/sky-req-prd-system/scripts/install.sh
```

开发分支使用 `git switch v1.1`；默认 main 仍是原稳定基线。install.sh 支持链接或 --copy，详情见脚本说明。

## 详细使用流程（产品经理的工作旅程）

### 第 1 步：定位或新建项目

```bash
python3 scripts/project.py discover /项目所在工作区     # 搜索已有项目
python3 scripts/project.py init /空目录 --name "项目名" --form web --version v0.1
```

一个产品一个项目；同产品的新需求是「新版本」，不会新建独立项目。

### 第 2 步：给零散需求，生成首版

把你的散点需求（几段描述、几条列表都行）交给 Agent，说明产品形态（web/mobile/…）与本次范围。技能会：按功能类型补细颗粒度（边界、异常、状态、验收——标注 AI 推断+待确认）、生成需求文档、可交互原型、测试与上线物料。

**可裁剪**：只要 PRD 或只要原型也行——裁剪会在概览显式列明未出项，后续说「补上测试」即可增量添加。

### 第 3 步：评审与拍板

- 左侧「本版变更与待确认」集中呈现全部待确认项（含是否阻塞开发）；
- 本机编辑器支持正式修改：`python3 scripts/edit_project.py /项目目录 --version v0.1`（需求、规则、实例、验收、Markdown 正文、原型属性；带预览/冲突检查/撤销）；
- 拍板结果回写 spec 转已确认；全部确认后可冻结：`project.py freeze`。

### 第 4 步：原型评审

- 「查看说明」模式：带规则的控件虚线现形，点击直达规则与验收；
- 「本页需求」面板：宽屏默认停靠，可拖拽/缩放/停靠/收起；
- 「编辑标记」：在控件或位置上就地新增批注（优先级+说明），支持撤销与 JSON 导出/导入；
- 场景切换：空数据/加载中/请求失败/无权限，真实呈现状态。

### 第 5 步：交付开发

- 「需求范围与交接」：按变化、待确认/阻塞、关注方向筛选，导出交接清单（Markdown/JSON）；
- 「复现链接」：把指定角色与异常状态发给开发，链接还原预设起点；
- 正式交接快照：`project.py handoff --revision r1`，冻结独立交接版本。

### 第 6 步：验收与上线

- 执行结果登记「验收结果与上线复盘」台账（环境/构建/执行人/证据）；
- 指标观测（基线/目标/实际/窗口）同台账记录，事后可更正（留历史）；
- 上线条件按四类清单逐项勾选（A 决策 / B 系统功能 / C 兼容环境 / D 质量流程）。

### 第 7 步：下一版迭代

```bash
python3 scripts/project.py new-version /项目目录 --version v0.2 --name "下一版主题"
```

继承当前物料作为基线，只改本次变化；旧版本快照不动。

## 配置你的个人标准（config.md）

编辑技能根目录的 `config.md`，把你的标准固化为默认约束。当前已内置（来自真实项目迭代沉淀）：细粒度规则带边界分类、描述一句话、禁冗余（单一来源+指针）、测试用例按模块分组含覆盖对照、上线条件四类结构、数据与埋点章默认提供、交付物默认完整可裁剪、概览三件套（目标↔需求映射表/交付物料表/版本范围）、隐私优先。改完即对下次生成生效。

## 生成的站点长什么样

```
项目名
├─ 项目总览与版本计划
└─ ▼ v0.1 · 主题（状态）
   ├─ ▸ 版本与需求范围（本版变更与待确认 / 需求范围与交接）
   ├─ ▼ 需求文档（九章：范围/用户/功能需求与规则/埋点/非功能/验收/里程碑/风险/附录）
   ├─ ▼ 交互原型（每个原型页可操作）
   ├─ ▼ 验收与测试（测试用例）
   ├─ ▼ 上线计划（含 AB 实验）
   └─ 验收结果与上线复盘（执行台账）
```

## 九章标准 PRD 与附件

新建项目采用九章 PRD：范围、用户流程、功能与页面规则、数据埋点、非功能、验收上线、里程碑、风险、附录。缺失信息标待补，不适用须说明原因。范围、页面需求及验收引用唯一来源，完整 Markdown 导出包含全部章节。

通过本机 PRD 编辑器的「附录 · 文件附件」上传真实文件，保存于项目 attachments/，支持说明和需求关联；静态 HTML 可下载，不可直接写磁盘。冻结后附件独立标注为补充资料。分享项目须包含附件目录。限制与旧项目升级说明见 references/standard-prd.md；本次更新 Skill 不会自动改写已有项目。

## 结构与迁移

```text
project/
├── project.json
├── build.py / projectlib.py
├── versions/
│   ├── v1.0/content/        # manifest、spec、文档、原型、测试与上线
│   └── v1.1/content/
└── site/index.html          # 项目固定入口
```

规划版可以修订；冻结、开发中、已发布版本保护内容快照，后续改动进入下一版。冻结是产品交付动作，需依据用户实际确认状态执行。

迁移原 1.0 项目：`python3 scripts/project.py migrate /项目目录 --version v1.0`。旧内容保留并创建 migration-backup，固定入口不变。技能外壳升级：`python3 scripts/project.py upgrade-shell /项目目录 --apply`。

## 附：1.1 变化清单

- 原型页稳定编号可见：左侧菜单、原型工具栏和页面路径共用页面 ID（例如 order-list）；通过 `revise_item.py --page order-list` 精确检索对应源 HTML、需求与控件。编号不随改名、排序或版本继承变化。
- 从已有 HTML 精确增量修改：`scripts/revise_item.py` 定位项目/版本与稳定 ID，预览并保存单字段变更；布局/行为由 Agent 局部修订源文件，不重生成项目。PRD 阅读页按业务标题、规则、验收组织，支持目录、搜索、控件技术折叠、Agent 定位信息及完整可读 Markdown 导出。
- 验收与上线复盘台账：原型/真实产品分开记录，保存环境、构建、执行人和证据；指标记录口径、基线、目标、实际及观察窗口。更正留历史、物料变动提示复核，跟进事项关联已有规划版本。浏览器支持 JSON 草稿导出，正式入库使用 `scripts/record_outcome.py`；不改冻结物料、不自动放行上线。
- 角色与状态复现链接：spec 声明合成场景，固定入口及独立原型链接还原指定版本、角色与初始数据；跨页演示隔离、重置不影响普通演示，失效场景明确拒绝。接入与权限行为验收见 references/replay.md。
- 批注处理闭环：待处理/采纳/驳回/完成、处理说明、需求及正式修改记录关联、验证说明与处理历史；修改批注内容会重新待处理。支持筛选和新版 JSON 导出，`scripts/review_notes.py` 只读核对本地需求与保存记录。
- 需求范围与交接：摘要、需求清单表格、单项分区详情；按变化、待确认/阻塞及关注方向筛选，查看规则、控件和验收，导出当前筛选的 Markdown 交接清单或 JSON 数据。分工与依赖按实际资料填写，不自动创建外部工单；原有入口链接继续可用。
- 同版本多次交接：`python3 scripts/project.py handoff <项目> --version v1.1 --revision r1`，冻结独立交接快照，保留可编辑草稿；左侧按产品版本归组，标明当前开发依据，历史深链接不跳转。
- 本机 PRD 编辑器：`python3 scripts/edit_project.py <项目目录> --version <规划版本>`。支持既有需求/规则/实例/验收及 Markdown 正文的正式编辑、变更预览、冲突检查、保存与撤销。详见 references/editing.md；原型业务脚本仍按影响报告复核。
- 同一编辑器支持点选布局预览修改原型文案、原生输入约束、选项、默认值、跳转目标与有限宽度；保存到 spec，runtime 应用。静态预览不运行页面脚本，实际交互需另行验证。
- 一个项目一个固定入口，左侧按版本组织全部物料。
- 新版本继承已有物料，只修改本次变化；冻结历史文档、原型和资源。
