# 轻量维护入口

用户修改已生成项目时只走本入口，不执行首次生成流程，不要求重读全部 references。先定位项目和版本，读取项目 config.md 的适用约束。自然语言由当前 Agent 理解，以下脚本不调用模型，也不会新建项目或版本。

1. `python3 <skill>/scripts/maintain.py '<本地项目或HTML深链接>' --version v1.1 --query '名称或编号'` 返回至多 50 项精简索引、版本状态及 revision。用 --key 精确读取一个文档/小节；结构化规则/控件用 revise_item.py 定位。远程网页必须先映射已有本地源目录。
2. 小节、埋点事件、测试用例、风险、里程碑、表格行使用明确、稳定的 `<!-- material: RISK-001 -->` 锚点，范围到下一个锚点前。重命名不改 ID。不要在 Markdown 表格内部插入注释打断表格；表格整体设置锚点，行使用第一列稳定 ID，再用唯一原文替换目标行。旧文档没有锚点时仍可按文件+唯一原文修改，不为一次小改重写所有文件补编号。
3. Markdown 局部补丁文件格式：`{"source":"prd/risks.md","anchor":"RISK-001","before":"原文","after":"修改后"}`。anchor 可省略；before 必须唯一匹配。`maintain.py <项目> --version v1.1 --patch <补丁.json> --revision <指纹>` 预览，加 --save 保存。写补丁使用 apply_patch。冲突/重复原文/冻结版拒绝覆盖，输出影响和撤销 ID，不返回整套物料。
4. 单规则/控件属性读取 incremental.md 的单字段入口；多项关联规则一次修改包读取 editing.md。布局/JS 按 selector 局部 apply_patch，读取受影响依赖及 prototype.md 的相关约束，不能改编译产物。新增功能或跨页面重大改变才进入范围规划。
5. 文字修订检查目标差异与引用；业务规则变动复核关联 PRD、页面脚本、提示、测试。运行 build/validate，按风险验证相关浏览器路径。Markdown 无结构化依赖时影响报告仍保守列全部页面，不误称已实现精准依赖分析。构建是程序编译，不让模型重写未变物料。

表格第一列已有稳定编号（如 EVT-001、TC-001、RISK-001）时自动登记 row 定位键；--key 返回该行，可用唯一原文补丁修改单个单元格或该行。索引读取和保存器在程序内部可能仍检查全项目，模型只接收候选/选中内容；不承诺已实现文件级增量编译或量化 token 降幅。

站点顶部“定位并交给 Agent”可选择索引中的物料，复制项目标识、版本、来源、编号与当前链接。此功能不向外部发送内容，不绑定某种 Agent，也不保证远程链接可以直接写回源目录。项目总览、交接汇总等派生节点只定位，不直接改汇总 HTML；应修改其 project.json/spec/文档/台账来源。附件元数据定位后沿用附件追加流程，不用正文补丁替换二进制。
