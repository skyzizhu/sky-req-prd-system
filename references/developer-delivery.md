# 需求范围与交接

用户要求交付给开发、导出交接清单或按开发关注点查看范围时读取。固定入口左侧“需求范围与交接”进入 `#/v/<版本>/_delivery/tasks`。路由沿用旧值以兼容已有链接；交接修订从其报告页进入，链接保持快照版本，不自动切换当前依据。

页面层次：紧凑交接摘要（版本/比较基线/开发依据）→ 需求清单 table → 选中需求的分区详情。表格列出名称/编号、变更类型、确认/阻塞、关注方向、依赖及查看详情按钮。详情按需求说明、规则与实例、验收、控件显示、分工依赖、相关物料组织，不使用 pre 展示整份 Markdown。筛选、表格、单项选择和导出保持同步；清空结果时不残留上一条详情。Markdown 交接清单包含同一筛选的概览表及完整正文，JSON 仍用于结构化交换，不承诺已拆分工时或创建外部工单。

工作版与 current_handoff（没有则 base）比较；交接快照与其固定 base 比较。界面明确工作草稿/冻结物料、比较基线与项目当前开发依据。

每条需求输出：新增/修改/移除/关联变化需复核、来源需求确认状态及阻塞属性、完整规则/实例、控件动作及属性、验收、需求/原型链接、分工与依赖。移除条目保留旧版链接和验收；需求子规则 pending 不能被父需求 confirmed 掩盖。确认只代表文档记录，不能自动宣称技术评审或真实测试通过。

有明确分工及依赖资料时，为需求填写可选字段：

```json
{"delivery":{"roles":["frontend","backend","qa"],"dependencies":["依赖订单状态查询接口；负责人和交付时间待确认"]}}
```

没有依据时不编造。缺分工时各角色筛选均保留并标待分工；空依赖展示“未登记，需评审”，不是无依赖。前端/后端/测试仅为关注方向，不是自动拆好的工时或实施方案。

支持关键词、仅本次变化、待确认、阻塞与角色筛选，导出当前筛选的 Markdown/JSON。交接清单来自与界面相同的数据，包含版本、基线和链接；不调用外部任务系统、不代替创建工单。file:// 导出的链接只在对应机器路径有效；团队分享应使用固定托管地址再导出，不能宣称本地路径是团队可用链接。

Markdown 面向人阅读：需求名称作为标题，依次组织业务规则、验收、控件显示说明和相关物料；稳定编号放在追踪信息中，不用编号代替正文。JSON 保留结构化 ID，供工具处理，不作为默认业务阅读稿。

结构化 PRD 页面提供需求目录、页面筛选、正文/编号搜索、业务规则分区、中文前提/操作/预期验收、按需展开的控件技术信息。完整 PRD 导出与交接筛选导出是两个入口：前者始终导出完整文档并明确标注，后者只导出当前筛选。PRD 正文不重复展开所有页面的控件索引；页面范围先用业务名称概述，技术定位保留在关联控件处。需要精确修改时从需求/控件获取 Agent 定位信息，见 incremental.md。

比较包含需求、交互与页面关联。共享代码、样式或正文变化无法自动确定业务影响时，保守将相关版本需求列为需复核，并在导出记录 changed_files；不以文件未变证明业务正确。缺旧 content_hashes 的旧构建需重建外壳数据，不能改写冻结内容。该模块只增加编译数据与外壳视图，不写历史物料。
